# Exec plans

Карта разделов и правила старта сессии. Политика создания планов — в [PLANS.md](../../PLANS.md).

## Разделы

| Раздел | Путь | Назначение |
|--------|------|------------|
| task | [inprogress/task/](./inprogress/task/) | План обязателен; не дефект и не крупная мультиподсистемная работа |
| bug | [inprogress/bug/](./inprogress/bug/) | Дефект: repro → fix → verify |
| big-task | [inprogress/big-task/](./inprogress/big-task/) | Много сессий / подсистем / открытых решений |
| hot-fixes | [inprogress/big-task/hot-fixes/](./inprogress/big-task/hot-fixes/) | Отклонение конкретного этапа родительского decompose (только big-task) |
| completed | [completed/](./completed/) | Сводный `*-result.md` на закрытую смысловую работу |
| ranking | [ranking/](./ranking/) | Оценка A–D каждой закрытой работы; реестр по итогам completed |

У `task` / `bug` / `big-task` одинаковый состав: папка + `*-plan.md` + `*-decompose.md`. Hot-fixes — только у big-task.

## Plan-once

1. **Фаза планирования** — при необходимости разведка кода; заполняются `*-plan.md` (включая карту контекста) и `*-decompose.md` с годными этапами.
2. **Сессии исполнения** — автономный цикл **внутри текущего этапа** по тексту plan + этого этапа (канон soft/hard — [AGENTS.md](../../AGENTS.md)). Не заново выводят цель работы из кода. Чтение кода — только из полей этапа «Читать» / «Менять», либо при верификации / hot-fix.
3. Тексты этапов после старта исполнения не переписывают. Отклонение **смысла** этапа — hard: hot-fix (big-task, если не меняет смысл остальных этапов) или запись в открытые решения + стоп и вопрос человеку. Soft-решения в скоупе этап не блокируют.

Этап **негоден**, если это однострочный заголовок без опоры на plan. Этап **годен**, когда из его текста и карты контекста в plan можно выполнить работу без повторного discovery. Не начинайте исполнение, пока карта контекста заполнена и как минимум текущий + следующий этапы годны.

## Старт сессии исполнения

Без широкого обхода репозитория. Шаг 0 sync с remote по [AGENTS.md](../../AGENTS.md) уже выполнен (иначе hard — исполнение не начинать).

1. [PROGRESS.md](../../PROGRESS.md) — блокер и следующий шаг.
2. [FEATURE.md](../../FEATURE.md) — контракт; путь `Exec plan:`.
3. `*-plan.md` — цель, скоуп, карта контекста, текущий шаг, открытые решения, хвост лога.
4. В `*-decompose.md` — **только текущий этап** (id из plan).
5. Код и файлы — только из полей этапа «Читать» / «Менять»; иначе этап не готов к исполнению (hard).
6. Крутить автономный цикл этапа до DoD этапа или hard-блокера; соседний этап в том же прогоне **не** стартовать.

Запрещено: заново выводить цель из кода; переписывать этапы decompose; начинать соседний этап в том же прогоне (даже после смены «текущего шага» в plan для handoff); ждать подтверждения на каждый soft-шаг внутри этапа.

При закрытии этапа заполните DoD этапа по схеме (ожидаемый результат → команда → результат прогона → артефакт). Статус этапа `готово` запрещён при неполных полях или однословной проверке; закрытие этапа подчиняется гейтам [AGENTS.md](../../AGENTS.md) в объёме этапа. DoD этапа не подменяет DoD фичи в FEATURE.md. При зелёном DoD — commit+push по AGENTS, затем handoff (plan / PROGRESS) и стоп. При hard — handoff без авто commit/push.

Если план ещё не заполнен — это фаза планирования: см. шаблоны в index выбранного типа и [PLANS.md](../../PLANS.md).
