# Ranking

Оценка **закрытой смысловой работы** (один `*-result.md` в completed). Не доменный scorecard продукта и не лог сессий.

Политика завершения — в [PLANS.md](../../../PLANS.md); шаблон итога — в [completed/](../completed/).

## Когда обновлять

Только при закрытии работы: заполнена секция «Оценка качества» в `*-result.md` и добавлена строка в реестр ниже. Обычная сессия исполнения этапа ranking не трогает.

## Шкала

- **A**: вся верификация проходит, чистая архитектура, читаемо для агента, стабильные тесты
- **B**: верификация проходит, в основном чисто, незначительные пробелы в читаемости или покрытии тестами
- **C**: частично работает, известные пробелы, некоторые участки кода трудны для понимания агентом
- **D**: не работает или серьёзные структурные проблемы

## Критерии одной работы

Оценивайте итог целиком (то, что зафиксировано в `*-result.md`), не «весь репозиторий»:

| Критерий | На что смотреть |
|----------|-----------------|
| Верификация | Прогоны из AGENTS.md / FEATURE DoD; сквозной путь; health-check. Полнота структурированных доказательств в result/FEATURE: команда, результат, артефакт (и дата/сессия). Пробел в структуре доказательств тянет критерий вниз так же, как пробел в покрытии. При неполной структуре или пункте «Не считается готовым» из AGENTS.md по этому критерию нельзя ставить A или B (потолок C) |
| Архитектура / границы | Соблюдение [docs/convention](../../convention/index.md) и STACK; нет второго каркаса «временно» |
| Читаемость для агента | Достаточно ли plan/result и кода, чтобы продолжить без re-discovery |
| Стабильность тестов | Нет молчаливых skip, flaky без записи риска |

Итоговая буква — худший существенный критерий, если один явно тянет вниз; иначе согласованный итог A–D.

Работа с проваленным гейтом AGENTS не должна попадать в реестр как нормально закрытая: сначала добить доказательства либо явно зафиксировать остаточный риск и потолок итога ≤ C.
