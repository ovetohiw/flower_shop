# Хот-фиксы

Отклонения конкретного этапа родительского big-task decompose. Не замена нового big-task / bug / task и не место для тихого rewrite родителя.

Общие правила plan-once — в [docs/exec-plans/index.md](../../../index.md) и [PLANS.md](../../../../PLANS.md).

## Когда сюда

Создавайте hot-fix, если на текущем этапе родительского плана:

- вскрылся пробел или ошибка скоупа;
- появился блокер, которого не было в plan;
- нужна точечная корректировка, не меняющая смысл остальных этапов.

Не создавайте hot-fix вместо нового типа работы.

## Именование

- `YYYY-MM-DD-short-topic/` — папка хот-фикса
- `YYYY-MM-DD-short-topic-plan.md` — план хот-фикса
- `YYYY-MM-DD-short-topic-decompose.md` — декомпозиция хот-фикса

## Шаблоны

Бриф должен быть self-contained относительно **родительского** plan (путь + id этапа). Широкий обход репозитория не требуется, если карта контекста родителя и поля этапа заполнены.

## Связи

- Родитель → [../](../) (plan + decompose big-task)
- В логе родителя допустима ссылка «см. hot-fix …» без правки текста этапов родителя
- Архив: отдельной папки в completed нет; суть входит в секцию Hot-fixes родительского `*-result.md` — [completed/](../../../completed/)

## Правила

- Один текущий шаг у hot-fix, как у любого exec plan.
- Запрещено менять формулировки / чеклист этапов родительского `*-decompose.md` ради hot-fix.
- Hot-fix без эскалации к человеку — только если не меняет смысл остальных этапов родителя; иначе hard (блокер в PROGRESS). Soft/hard — [AGENTS.md](../../../../AGENTS.md).
- Исполнение hot-fix — автономный цикл текущего этапа после sync по AGENTS.md; при зелёном DoD — commit+push по AGENTS, затем handoff и стоп.
- Статус этапа `готово` запрещён, если поля DoD этапа неполные или проверка однословная (объём этапа; не подмена FEATURE DoD). Гейты и «не считается» — [AGENTS.md](../../../../AGENTS.md).
- При закрытии hot-fix: стадия «готово» в его plan, лог и DoD этапа заполнены.
- При завершении родительской работы перенесите суть всех связанных hot-fixes в `*-result.md`.
