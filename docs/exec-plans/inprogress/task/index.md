# Task

Плановая работа, которая не дефект и не крупная мультиподсистемная big-task. Состав артефактов тот же: plan + decompose. Hot-fixes здесь нет.

Общие правила plan-once и старта сессии — в [docs/exec-plans/index.md](../../index.md) и [PLANS.md](../../../PLANS.md).

## Когда сюда

- план обязателен по [PLANS.md](../../../PLANS.md) или нужен для передачи контекста между сессиями;
- это не баг-фикс и не работа масштаба big-task;
- достаточно одной линии этапов без ветвления через hot-fixes.

## Именование

- `YYYY-MM-DD-short-topic/` — папка плана
- `YYYY-MM-DD-short-topic-plan.md` — общий план
- `YYYY-MM-DD-short-topic-decompose.md` — декомпозиция

## Шаблоны

Скопируйте в папку плана и заполните **до** сессий исполнения. Карта контекста и этапы должны быть годными (см. корневой index).

## Связи

- Контракт фичи → [FEATURE.md](../../../FEATURE.md) (`Exec plan:` = путь этой папки)
- Сессионный лог → [PROGRESS.md](../../../PROGRESS.md)
- Архив → [completed/](../../completed/)
- Оценка при закрытии → [ranking/](../../ranking/)

## Правила

- Не начинайте исполнение, пока карта контекста заполнена и текущий + следующий этапы годны.
- Тексты этапов после старта исполнения не менять; статусы и лог в plan — да.
- Soft-решения в скоупе — в открытые решения / лог plan, цикл продолжать. Отклонение смысла этапа — hard (открытые решения + стоп), не тихий rewrite. Soft/hard — [AGENTS.md](../../../AGENTS.md).
- Старт исполнения — после sync по AGENTS.md. При зелёном DoD этапа — commit+push по AGENTS, затем handoff и стоп; соседний этап в том же прогоне не стартовать.
- Статус этапа `готово` запрещён, если поля DoD этапа неполные или проверка однословная (объём этапа; не подмена FEATURE DoD). Гейты и «не считается» — [AGENTS.md](../../../AGENTS.md).
- При завершении: один `*-result.md` в completed (с «Оценкой качества») и строка в ranking.
