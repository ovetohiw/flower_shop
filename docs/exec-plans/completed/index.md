# Завершённые работы

Архив сводных итогов exec plans. Политика завершения — в [PLANS.md](../../../PLANS.md); карта разделов — в [docs/exec-plans/index.md](../index.md).

## Когда сюда

Смысловая работа закрыта: гейты FEATURE/DoD из AGENTS.md пройдены (если фича применима), секция «Верификация» в result заполнена по схеме (не однословно), активные артефакты inprogress можно убрать после записи result. Не переносить сюда работу с несработавшими гейтами или пунктом «не считается».

## Именование

В `completed/` **нет** подразделов по типам.

- `YYYY-MM-DD-short-topic/` — папка итога
- `YYYY-MM-DD-short-topic-result.md` — единственный сводный файл

Тип (`bug` | `task` | `big-task`) — поле внутри `*-result.md`. Hot-fixes не создают отдельных папок: входят секцией в result родителя.

## Как завершать

1. Соберите решения из inprogress (plan, decompose, hot-fixes).
2. Создайте папку и один `*-result.md` по шаблону ниже (включая «Оценка качества»).
3. Добавьте строку в реестр completed (новые сверху).
4. Добавьте строку в реестр [ranking/](../ranking/) и обновите «Текущий снимок» там.
5. Уберите или очистите активные артефакты inprogress — канонический итог живёт в `*-result.md`.

`*-result.md` — сводка, не копия папок inprogress.

## Шаблоны

### `*-result.md`

```markdown
# Результат: {название}

## Мета

- Дата завершения:
- Тип: bug | task | big-task
- ID:
- Название:

## Цель

-

## Принятые решения

Сводка из plan и decompose (без дословного дублирования всего текста).

-

## Hot-fixes

Если хот-фиксов не было — напишите «нет».

- ID / название:
  - Этап родителя:
  - Суть решения:
  - Верификация:

## Верификация

Схема полей как в AGENTS.md / FEATURE.md (критерий или уровень → команда → результат → артефакт). Сводка или ссылка на «Доказательства DoD» в FEATURE. «Оценку качества» заполняйте после этой секции и опирайтесь на неё. Неполная или однословная секция — закрытие запрещено (гейты AGENTS).

- Гейты AGENTS пройдены: да | нет
- Источник доказательств FEATURE:
- Критерий / уровень:
  - Команда / действие:
  - Результат:
  - Артефакт:
  - Дата / сессия:

## Оценка качества

Шкала и критерии — [ranking/](../ranking/). Заполняйте после «Верификация»; оценки ссылаются на факты выше, не на ощущение.

- Итог: A | B | C | D
- Верификация:
- Архитектура / границы:
- Читаемость для агента:
- Стабильность тестов:
- Ключевые пробелы:
- Запись в ranking: docs/exec-plans/ranking/index.md

## Остаточные риски

-

## Источники inprogress

Пути к артефактам на момент завершения.

-
```

## Связи

- Активные планы → [inprogress/](../inprogress/)
- Оценка закрытых работ → [ranking/](../ranking/)
- Контракт и DoD → [FEATURE.md](../../../FEATURE.md)

## Правила

- Не удаляйте завершённую работу без сводного `*-result.md`.
- Полный текст итога — только в `*-result.md`; реестр — краткие ссылки.
- Без заполненной «Верификации» по схеме доказательств (включая «Гейты AGENTS пройдены: да»), «Оценки качества» и строки в ranking работа не считается закрытой по процессу.
- Перенос в completed при несработавшем гейте или пункте «Не считается готовым» из AGENTS.md запрещён.
