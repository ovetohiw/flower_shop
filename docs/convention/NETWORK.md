Читай при любом сетевом коде, HTTP/gRPC, внешних зависимостях. Протоколы — [STACK.md](../../STACK.md).

## Контракты

- Валидируй вход/выход: схема, размер, тип, обязательные поля.
- Ломающий публичный контракт — осознанно (FEATURE/план), не «заодно».
- Внутренний и внешний API не смешивай без решения.
- Имена полей стабильны.
- Стиль API не в STACK → второй стиль «временно» запрещён.
- Протокол/брокер/API-стиль вне STACK — запрещены.

## TLS и транспорт

- Не отключай проверку TLS/сертификатов; локальный обход не коммить ([SECURITY.md](./SECURITY.md)).
- Не отключай CORS/origin ради сценария без решения в плане.
- Секреты не в query, фрагментах URL, логируемых заголовках.
- Cookie/токены — по защищённому каналу там, где ожидается.
- Порт наружу не шире нужного; `0.0.0.0` без причины фиксируй явно.

## Таймауты

- У каждого исходящего вызова — таймаут. Бесконечное ожидание запрещено.
- Пользовательский вызов короче фоновой синхронизации.
- При отмене клиента привязывай фон к контексту отмены, если стэк умеет.
- Таймаут = отказ, не пустой успех.
- Вложенные вызовы укладывай в бюджет внешнего запроса.

## Ретраи

- Только безопасные/идемпотентные операции. Слепой ретрай `POST` без ключа идемпотентности запрещён.
- Лимит попыток + backoff.
- После исчерпания — явный отказ.
- Логируй номер попытки ([LOGGING.md](./LOGGING.md)), без spam.

## Ошибки

- Различай сетевой сбой, таймаут, 4xx, 5xx.
- Клиенту — безопасное сообщение ([SECURITY.md](./SECURITY.md)).
- Fallback к «разрешено» или устаревшим данным без пометки запрещён.
- Частичный успех при нескольких вызовах фиксируй.
- Поведение при сетевой ошибке — [TEST.md](./TEST.md).

## Зависимости и вход

- Исходящий вызов именуй; URL не размазывай по домену без обёртки границы.
- URL/ключи/таймауты — из конфига.
- Из тестов не ходи в прод и живой интернет ([TEST.md](./TEST.md)).
- Новая зависимость — STACK под текущую фичу.
- Деградация — явно: отказ / кэш с пометкой / очередь.
- Не доверяй заголовкам/IP/полям клиента для прав/цены/владельца ([SECURITY.md](./SECURITY.md)).
- Лимитируй размер тела и число заголовков.
- «CORS allow all» без решения в плане запрещён.
- Health/readiness — без секретов клиента и без тяжёлой логики.
- Публичный эндпоинт без auth — только если явно задумано и проверено.

## Версии, нагрузка, топология

- Ломающее изменение — версия или миграция клиентов; риск иначе в PROGRESS.md.
- Поля «на будущее» пачками не добавляй.
- Устаревший эндпоинт — по плану, не молча в багфиксе.
- Списки — пагинация/лимит; лишние данные не тяни.
- WebSocket/SSE — только STACK + нужда фичи.
- Лимиты частоты в проде не отключай тихо.
- Prod-хост не зашивай в код; в репо — плейсхолдеры.
- Новый внутренний сервис/сеть между частями — только Микросервис в STACK или план; при Монолите — внутри процесса ([ARCHITECTURE.md](./ARCHITECTURE.md)).

- Нельзя проверить сеть → hard в PROGRESS.md.
