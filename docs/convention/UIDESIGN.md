## Цель

- Экран отвечает «что сделать пользователю», не «чем заполнить пустоту».
- Визуальная правда при наличии файлов — [refs/](../../refs/). Пустой refs ≠ лицензия на новый язык.
- Не изобретай второй визуальный язык на одном экране.
- Новый приём — только если существующий не покрывает роль.
- Frontend/Стилизация не в STACK → не ставь библиотеку и второй способ стилей «временно».

## Композиция

- Первый вьюпорт — одна композиция. Дашборд из равнозначных блоков — только если экран и есть дашборд.
- Один главный фокус.
- Секция — одна работа: заголовок + обычно одно пояснение.
- Бренд на брендированной странице — сигнал уровня героя; заголовок не перебивает бренд.
- Без навигации первый экран нельзя принять за другой продукт.
- Бюджет героя на промо: бренд, один заголовок, одно пояснение, одна группа действий, один образ.
- В первый вьюпорт не клади статистику, расписания, адреса, «на этой неделе», второй маркетинг.

## Типографика и цвет

- Шрифт осознанный; Inter/Roboto/Arial/system без решения — не выбор.
- Цвет/ритм — токены; разрозненные литералы запрещены.
- Одно направление. Фон строит атмосферу; плоская заливка «чтобы было» — не направление.
- Главный образ — продукт/место/контекст; декоративный градиент главным не считается.
- Не скатывайся в клише: фиолетовый/индиго градиент; крем + serif + терракота; газетная сетка.
- Не тянись по умолчанию к тёмной теме, фиолетовому, свечению, пилюлям, многослойным теням, эмодзи — только записанный язык продукта.

## Макет

- Карточек нет по умолчанию; карточка = контейнер взаимодействия. Убрал рамку/тень/фон/radius и смысл жив → не карточка.
- В герое карточек нет.
- Промо-герой край в край; врезанный/боковой/скруглённая медиа/коллаж/плавающий блок — только если уже язык системы.
- На медиа героя — без оторванных бейджей/стикеров/чипов.
- Не заполняй экран пилюлями, полосами статистики, рядами иконок, коробочными промо.
- Критический путь на десктопе и мобильном.
- Плотность админки ≠ плотность промо.

## Компоненты и состояния

- Повтори паттерн репо; второй набор кнопок/полей/отступов запрещён.
- Примитив — когда уже повторяется; design system «на будущее» запрещён.
- Не создавай второй theme/токены/папку компонентов.
- Состояния явны: default, hover, focus, disabled, loading, empty, error.
- Пусто/ошибка говорят что случилось и что делать; не вечный спиннер.
- Загрузка не блокирует всё зря; макет не прыгает.
- Контрол подписан; иконка без имени — только устойчивый смысл + не только зрение.

## Движение

- Присутствие и иерархия, не шум.
- На ведущем экране — несколько осознанных движений.
- Не задерживай действие анимацией; учитывай `prefers-reduced-motion`.
- Не анимируй всё подряд.

## Контент и доступ

- Пояснение короткое; не дублируй заголовок.
- Ошибка пользователю безопасна ([SECURITY.md](./SECURITY.md)); логи — [LOGGING.md](./LOGGING.md).
- Скрытие кнопки/меню/поля ≠ проверка прав ([SECURITY.md](./SECURITY.md)).
- Доменное правило не копируй на клиент ([ARCHITECTURE.md](./ARCHITECTURE.md)).
- Секреты/токены/лишние ПДн в UI запрещены.
- Клавиатура, видимый фокус, порядок фокуса = порядок задачи.
- Смысл не только цветом; достаточный контраст; alt у смысловых изображений.
- Поле связано с подписью и ошибкой; hit-area достаточна на мобильном.

## Стэк UI

- Библиотека/стили — STACK; смена — отметка + plan ([PLANS.md](../../PLANS.md)).
- Язык репо > вкус и туториал.
- Токены/шрифты/примитивы — в одном месте.
- Тёмная тема/плотность/варианты бренда — только нужда продукта.

## Запрещено

- God-экран в первом вьюпорте.
- Карточка «чтобы заметно».
- Второй theme; библиотека вне STACK.
- Защита только UI; клише сгенерированного вида; эмодзи/свечение/тени вместо иерархии.
- Пустой экран / вечный скелет / ошибка без следующего шага; одна ширина.

## Проверка

- Критический путь на десктопе и мобильной ширине обязателен.
- Наблюдаемое поведение — [TEST.md](./TEST.md); не привязывайся к случайной вложенности разметки.
- «Выглядит нормально» без проверки ≠ доказательство ([FEATURE.md](../../FEATURE.md) / [AGENTS.md](../../AGENTS.md)).
- Сверь с [refs/](../../refs/), если есть; расхождение без записи — дефект.
- Неочевидный язык → PROGRESS.md / план.
- Не помечай UI готовым без двух ширин.
