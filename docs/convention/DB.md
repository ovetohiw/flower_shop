## Выбор

- СУБД/ORM/миграции вне STACK — запрещены; не выбирай «по пути».
- Одна основная транзакционная БД, пока не Микросервис + второе хранилище в стэке/плане ([ARCHITECTURE.md](./ARCHITECTURE.md)).
- Монолит: не дроби схему «под будущие сервисы».
- Микросервис: своя БД на сервис; общая БД между сервисами без решения запрещена.
- Доступ к данным — один слой; UI/HTTP не ходят в БД напрямую ([ARCHITECTURE.md](./ARCHITECTURE.md)).
- Кэш/поиск/аналитика не подменяют транзакционную БД без STACK.

## Схема

- Имена отражают содержимое (`temp`, `data2`, `fix`, `misc` запрещены).
- Не переименовывай «заодно»; один стиль имён.
- Тип/nullable/default осознанно; не «строка на всё».
- Поля «на будущее» пачками не добавляй.

## Миграции

- Любое изменение схемы — миграция в репо; ручной ALTER не заменяет.
- Обратимость или явный план отката.
- Применённую в общей ветке миграцию не правь — только новая.
- Порядок применения один локально / CI / выкат.
- Риск потери данных — в PROGRESS.md или плане.
- Пустую / «починить вручную» миграцию не оставляй.
- Схему руками на сервере не правь; ограничения целостности не отключай ради сценария.

## Запросы

- Только параметризованные; не склеивай SQL/фильтры/имена колонок из ввода ([SECURITY.md](./SECURITY.md)).
- Фильтр доступа — на сервере, не из полей клиента.
- Только нужные колонки; `SELECT *` / запись всей сущности «на всякий случай» запрещены при растущей схеме.
- Списки — пагинация/лимит.
- Ошибку БД, отказ ограничения и «не найдено» различай; не своди к пустому успеху.

## Транзакции и индексы

- Связанные записи вместе — одна транзакция.
- Конфликт уникальности / FK / дедлок — явный отказ.
- Частичная запись ≠ успех.
- Повтор создающей операции — идемпотентный ключ или unique.
- Индекс — под запрос текущей фичи, в миграции.
- N+1 / scan без лимита — исправь или риск в PROGRESS.md.
- Таймаут к БД обязателен, если стэк умеет ([NETWORK.md](./NETWORK.md)).

## Данные и среды

- Креды — из конфига; в репо — `CHANGE_ME` ([SECURITY.md](./SECURITY.md)).
- Не коммить дампы, прод-данные, строки подключения.
- Тестовая БД изолирована ([TEST.md](./TEST.md)); фикстуры без секретов/лишних ПДн.
- Истина схемы — миграции, не локальная БД.
- Soft-delete/ретенция/архив — только если нужны фиче и в контракте.
- Удаление ПДн явно; бэкап не выдумывай в коде фичи без STACK/плана.
- Сиды — миграция или явный сид, не ручная вставка на сервере.

## Наблюдаемость

- Не логируй SQL с секретами/ПДн и строку подключения ([LOGGING.md](./LOGGING.md)).
- Клиенту — безопасное сообщение ([SECURITY.md](./SECURITY.md)).
- Health отражает критичную БД без тяжёлой логики.
- Нет миграции / явного отказа / проверки → не готово ([TEST.md](./TEST.md)); иначе hard в PROGRESS.md.
- Не подменяй проверку хранения моком той же логики, если сценарий про БД.
