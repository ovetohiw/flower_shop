# LOGGING.md

**Для агента.** Канон: уровни, формат, корреляция, запрет print, маскирование полей в логах.
Не канон: что секрет / ответ клиенту ([SECURITY.md](./SECURITY.md)); Mono/Micro ([ARCHITECTURE.md](./ARCHITECTURE.md)); DoD ([AGENTS.md](../../AGENTS.md)).
Читай, когда добавляешь/меняешь логи или трогаешь вывод ошибок. Библиотеки — [STACK.md](../../STACK.md).

### Связи

- Карта → [index.md](./index.md)
- Соседи: [SECURITY.md](./SECURITY.md) · [ARCHITECTURE.md](./ARCHITECTURE.md) · [NETWORK.md](./NETWORK.md) · [TEST.md](./TEST.md)

**Нарушение** — секрет/лишние ПДн в логе, `print` вместо логгера, лог вместо обработки ошибки, лог без контекста.

## Когда писать

- Лог = «что произошло в системе».
- Пиши на границах: вход, отказ, внешний вызов, смена состояния, необработанная ошибка.
- Не логируй каждую строку «на всякий случай».
- Счастливый путь — редко; подробности — на ошибках.
- Лог ≠ метрика/алерт/тест. Не чини отсутствие проверки через `print`.

## Уровни

- `debug` — локально; в проде выключен/ограничен.
- `info` — штатное значимое без секретов.
- `warn` — ещё не сбой (повтор, деградация, лимит).
- `error` — операция не выполнена.
- Не завышай (валидация ≠ `error`) и не занижай (потеря данных ≠ `info`).

## Формат

- Структурированные поля > склейка текста.
- Сообщение короткое и стабильное; переменные в полях.
- Минимум: время, уровень, сообщение, сервис/модуль, correlation/request id.
- Имена полей едины; синонимы `requestId`/`req_id` без решения запрещены.
- Пока формат не в STACK — один канал; второй «временно» не вводи.

## Корреляция

- На входе — correlation id через обработку.
- Микросервис: через границы сервисов; Монолит: процесс/модуль ([ARCHITECTURE.md](./ARCHITECTURE.md)).
- Id сущностей для поиска — без секретов и полных документов.
- Внешний вызов: направление, зависимость, исход; не дампь весь ответ.
- Воркер тоже несёт корреляцию. Пустой `error` без id/причины — нарушение.

## Что нельзя писать

- Секреты/ПДн — [SECURITY.md](./SECURITY.md). Здесь: маскируй (хвост/хеш); не логируй тела целиком при риске секретов.
- Те же запреты в FEATURE, PROGRESS, планах, CI, ответах в чат; тестовый вывод = лог.
- Сомнительное поле → не пиши; вопрос в PROGRESS.md.
- Не логируй секреты «для отладки».

## Ошибки

- Логируй где обрабатываешь окончательно или теряется контекст; не дублируй стек на каждом слое.
- Тип отказа и причина обязательны.
- Стек — во внутренний лог; клиенту — [SECURITY.md](./SECURITY.md).
- Лог не заменяет проброс/явный отказ. Не подменяй обработку одним логом с успешным продолжением.
- Ретраи — номер попытки + исход; spam запрещён ([NETWORK.md](./NETWORK.md)).

## Объём и консоль

- Прод — минимум для расследования; не логируй в цикле без нужды.
- Ротация/ретенция — конфиг, не хардкод в домене.
- Прод-логи не в репо и не в публичные бакеты без контроля.
- Debug-дампы payload не по умолчанию и не коммить включёнными.
- `print` / `console.log` в постоянном коде запрещены при наличии логгера; не оставляй в коммите.
- ORM не должна печатать SQL с данными и секреты подключений в обычном режиме.
- Новый пакет логирования — только STACK ([DEVELOPMENT.md](./DEVELOPMENT.md)).

## Проверка

- Секрет виден в логе счастливого/ошибочного пути → не готово.
- Нельзя проверить маскирование → риск в PROGRESS.md ([TEST.md](./TEST.md)).
- Смена формата/бэкенда логов — STACK/план, не побочный эффект.
- DoD — [AGENTS.md](../../AGENTS.md).
