Не канон: маскирование в логах ([LOGGING.md](./LOGGING.md)); TLS/таймауты ([NETWORK.md](./NETWORK.md)); SQL/миграции ([DB.md](./DB.md)); UI-скрытие контролов ([UIDESIGN.md](./UIDESIGN.md)).
Читай, когда задача трогает доступ, секреты, ввод с клиента или ответы наружу. Библиотеки — [STACK.md](../../STACK.md).

**Нарушение** — секрет в репо/ответе/доках, ослабленный authz, доверие клиенту, обход защиты ради скорости или зелёного теста.

## Секреты и конфиги

- Не коммить `.env`, ключи, токены, пароли, приватные сертификаты, дампы.
- В репо — только `CHANGE_ME`-плейсхолдеры.
- Не вставляй секреты в URL, query, FEATURE, PROGRESS, планы, скриншоты, вывод тестов, CI, ответы в чат.
- Маскирование runtime-логов — [LOGGING.md](./LOGGING.md).
- Утечка в git/чат → считай скомпрометированным; удаление из последнего коммита не отменяет ротацию.
- Не копируй секреты из окружения в документы, примеры и ответы.

## Аутентификация и доступ

- Authz только на сервере. Скрытие кнопки ≠ защита ([UIDESIGN.md](./UIDESIGN.md)).
- Минимальные права сервису/пользователю/токену.
- Не хардкодь учётки, пароли, «войти как админ», debug-backdoor, скрытый админ-маршрут.
- Пароли — только стойкий хеш.
- Сессию/токен в `localStorage` — только с явным решением в плане.
- Срок жизни и отзыв токена задай до готовности фичи.
- Не ослабляй authz/валидацию ради зелёного теста.
- Тестовый обход auth — только в тестовом коде ([TEST.md](./TEST.md)).

## Ввод и данные

- Валидируй ввод на границе системы, не только в форме.
- SQL — параметризованный; канон — [DB.md](./DB.md).
- Не доверяй полям клиента: роль, цена, владелец, флаги прав.
- Санитизируй вывод в HTML/шаблон/команду.
- Upload: тип, размер, имя; путь клиента ≠ путь на диске.
- Отказ/ошибка разбора — явно; fallback к «разрешено» запрещён.

## Ответы клиенту

- Наружу — безопасное сообщение. Стек, SQL, внутренние пути — не ответ клиенту.
- Request id допустим; секрет в нём — нет.
- Внутренние логи ошибок — [LOGGING.md](./LOGGING.md).

## Зависимости и поставка

- Пакет/образ/сервис — только нужен фиче и в STACK ([DEVELOPMENT.md](./DEVELOPMENT.md)).
- TLS не отключай — [NETWORK.md](./NETWORK.md).
- Production-секреты не в Dockerfile/Compose/CI-файлах репо; CI — через хранилище платформы.
- Не `eval` / shell из пользовательского ввода.
- Уязвимые зависимости обнови до безопасного выката.

## Git и артефакты

- Перед коммитом: diff без секретов и реальных ПДн. Commit/push — [AGENTS.md](../../AGENTS.md).
- Не обходи хуки ради спорного файла.
- Временный обход защиты не коммить и не включай по умолчанию.
