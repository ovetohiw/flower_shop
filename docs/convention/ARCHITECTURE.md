# ARCHITECTURE.md

**Для агента.** Канон: слои, границы модулей, публичные контракты, Монолит / Микросервис, эволюция границ.
Не канон: diff/имена ([DEVELOPMENT.md](./DEVELOPMENT.md)); сеть ([NETWORK.md](./NETWORK.md)); схема БД ([DB.md](./DB.md)); секреты ([SECURITY.md](./SECURITY.md)); DoD ([AGENTS.md](../../AGENTS.md)).
Читай, когда кладёшь код в слой, меняешь границы, режешь сервисы или трогаешь STACK «Архитектура».

### Связи

- Карта → [index.md](./index.md)
- Соседи: [DEVELOPMENT.md](./DEVELOPMENT.md) · [NETWORK.md](./NETWORK.md) · [DB.md](./DB.md) · [SECURITY.md](./SECURITY.md)

**Нарушение** — слой с чужими деталями, цикл зависимостей, второй каркас «временно», Mono↔Micro без STACK и плана.

## Ограничения размещения

- Клади поведение туда, где уже живёт роль. Параллельная папка с той же ролью запрещена.
- Новый слой/сервис/`shared` — только если роли ещё нет; отдельный деплой — только при Микросервисе в STACK.
- Куда класть неочевидно → повтори паттерн репо или вопрос в PROGRESS.md (hard при смене смысла границ).
- Туториал стэка не перебивает принятые границы репо.

## Слои

- Вход (UI/HTTP/CLI) → прикладная логика → данные/внешние системы. Зависимости внутрь.
- Внутренний слой не знает транспорт, разметку, UI-фреймворк вызывающего.
- UI/вход не ходят в хранилище напрямую ([DB.md](./DB.md), [NETWORK.md](./NETWORK.md)).
- Не протаскивай типы БД/ORM/сырые ответы внешних API через все слои.
- Круговые импорты запрещены; не чини циклы глобалом/ленивым импортом.

## Модули и контракты

- Модуль — одна роль; не смешивай разбор запроса, правило и SQL «потому что коротко».
- Новый паттерн — отдельное решение ([DEVELOPMENT.md](./DEVELOPMENT.md)).
- `shared` «на будущее» запрещён; общий код — когда поведение уже повторяется.
- Наружу — минимальный контракт.
- Публичный контракт ломай только с версией/планом ([NETWORK.md](./NETWORK.md)); имена стабильны.

## STACK: Монолит / Микросервис

- Источник истины — STACK «Архитектура». Смена — отметка + exec plan ([PLANS.md](../../PLANS.md)).
- Пока не отмечено — не нарезай сервисы и не вводи второй стиль; не выбирай «по пути».
- Ровно один вариант; оба сразу — дефект стэка → стоп.

### Монолит

- Границы — модули/слои в репо, не сеть между «сервисами».
- Новый HTTP/gRPC-сервис «для ясности» запрещён.
- Общая БД внутри монолита нормальна, пока иное не в STACK.

### Микросервис

- Своя граница и контракт на сервис.
- Связь через сеть/очередь/событие, не через чужую БД/внутренние модули.
- Новый сервис — STACK или план.
- Частые sync без нужды и общая БД между сервисами без решения запрещены.

## Композиция и состояние

- Оркестрация — в прикладном слое; транспорт только принимает/отдаёт.
- Фон/воркеры — те же правила зависимостей.
- Новый процесс/канал, меняющий архитектуру — STACK/план.
- Побочные эффекты (БД/сеть/очередь/ФС) — явно на границе.
- Идемпотентность повторов — на границе ([NETWORK.md](./NETWORK.md)).
- Время/случайность/внешний мир — на краю ([TEST.md](./TEST.md)).
- Конфиг из окружения; секреты — [SECURITY.md](./SECURITY.md).
- Feature-flag ≠ второй постоянный каркас; заглушки не в прод-путь без стэка/плана.

## Ошибки и эволюция

- Явные отказы; не подменяй пустым успехом ([DEVELOPMENT.md](./DEVELOPMENT.md)).
- Клиенту — безопасное сообщение; стек/SQL — лог ([SECURITY.md](./SECURITY.md), [LOGGING.md](./LOGGING.md)).
- Локальная фича не переписывает STACK «Архитектура».
- Рефакторинг границ рядом — только если без него нельзя.
- Старый паттерн не оставляй «навсегда рядом» без плана вывода.

## Запрещено

- God-модуль; «утилита» на полсистемы; второй доступ к тем же данным.
- Копия домена на клиенте и сервере без источника истины.
- Микросервисы при Монолите; монолитный комбайн без модулей при Микросервисе.
- Смена архитектуры без правки STACK.

## Проверка

- Поведение не в том слое / утечка деталей наружу → не готово.
- Тест через «дыру» слоя архитектуру не доказывает ([TEST.md](./TEST.md)).
- Неочевидная граница → PROGRESS.md / план.
- DoD — [AGENTS.md](../../AGENTS.md).
