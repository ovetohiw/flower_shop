# TEST.md

**Для агента.** Канон: когда обязателен тест, уровни, изоляция, моки, прогон.
Не канон: DoD и доказательства ([AGENTS.md](../../AGENTS.md), [FEATURE.md](../../FEATURE.md)); секреты в фикстурах ([SECURITY.md](./SECURITY.md)); Mono/Micro ([ARCHITECTURE.md](./ARCHITECTURE.md)).
Читай, когда пишешь/правишь/прогоняешь тесты или закрываешь критерий приёмки. Раннеры — STACK / AGENTS.

### Связи

**Нарушение** — фича без проверки поведения, нестабильный/удачный тест, ослабленный assert ради зелёного, выдуманный успешный прогон.

## Когда тест обязателен

- Новая/изменённая фича не сделана без проверки поведения.
- Багфикс — с регрессией (падает на старом, проходит на новом).
- Security-поведение — тестом, не «на глаз» ([SECURITY.md](./SECURITY.md)).
- Доказательства — AGENTS / FEATURE. Код без прогона ≠ доказательство.
- Мелкая правка текста/стиля без смены поведения — можно без нового теста, если базовая верификация зелёная.
- При сомнении — проверка поведения, не снапшот реализации.

## Уровни

- Unit — одна единица без внешних систем.
- Интеграция — граница (API/БД/очередь) на тестовых данных, не прод.
- Микросервис: критичный путь между сервисами — контракт/интеграция на границе, не только внутренний мок ([ARCHITECTURE.md](./ARCHITECTURE.md)).
- Сквозной — критический пользовательский путь; не дублируй каждую unit-ветку.
- Сквозной невозможен → риск в PROGRESS.md; не подменяй тестом, который не трогает поведение.
- Не подменяй сквозной критический путь unit-тестом на моках.

## Что проверять

- Наблюдаемое: вход, выход, ошибка, отказ, побочный эффект на границе.
- Не привязывайся к приватной реализации, порядку внутренних вызовов, случайной разметке.
- Не тестируй фреймворк и нетронутый сторонний код.
- Снапшот — только узкий стабильный контракт.
- Один сценарий — одна причина падения.

## Изоляция

- Не зависит от порядка, чужих данных, машины.
- Время/случайность/сеть — явно. Живой интернет, прод, «сейчас» без подмены запрещены.
- Фикстуры создать и убрать; база не остаётся грязной.
- Нестабильный тест — чини или выведи из обязательного с записью в PROGRESS.md. Молчаливый skip и «повтор до зелёного» запрещены.
- Не глуши ошибку и не расширяй допуск ради зелёного.

## Данные

- Нет реальных секретов/лишних ПДн в фикстурах и выводе ([SECURITY.md](./SECURITY.md)).
- Обход auth — только в тестовом коде, не в обычном запуске.

## Имена и структура

- Имя = что происходит + ожидаемый результат (`test1` запрещён).
- Подготовка → действие → проверка.
- Данные минимальны; уровни не смешивай в одном файле без причины.

## Моки

- Мокай границу (сеть, внешний сервис, часы, ФС), когда реальный ресурс не нужен.
- Не мокай модуль, который проверяешь.
- Реальная связка важнее моков, копирующих ту же логику.
- Мок — только нужное сценарию.

## Прогон

- Команда — из AGENTS.md или STACK.md. Раннер не выдумывай.
- Локально — затронутые тесты + базовая верификация AGENTS, когда задана.
- CI обязательный набор = базовая верификация; локально зелёное / CI красное → не готово.
- Красный обязательный тест / неполный гейт → блок DoD ([AGENTS.md](../../AGENTS.md)).
- Нельзя прогнать → hard: блокер в PROGRESS.md, не выдумывай успех.
